# Legendary Online 学习路线

## 1. 学习目标

本项目的目标不是让开发者复制出一个表面可运行的项目，而是让已有 Java Web、Spring Boot 经验的开发者逐步掌握 Java 游戏服务端的运行模型：

- 理解 TCP 长连接和 Netty 事件驱动模型。
- 理解网络线程、业务线程和场景 Tick 线程之间的边界。
- 理解 Protobuf Schema、二进制消息头和拆包粘包处理。
- 理解服务端权威移动、战斗结算和状态广播。
- 能够通过测试、日志、JFR 和 Bot 定位实时服务端问题。

本项目的具体学习起点和短板见 [个人学习画像](个人学习画像.md)，项目能力与就业岗位的映射见 [就业证据矩阵](就业证据矩阵.md)。

## 2. 每个阶段的固定流程

每当阶段引入新的基础组件时，先在 `docs/组件说明/` 下创建组件说明文档，再开始编写业务代码。组件文档与代码注释配合使用：组件文档讲完整概念和选型背景，代码注释解释当前类和参数为什么这样落地。

### 2.1 概念先行

实现前先回答：这个组件解决什么问题？它运行在哪个线程？输入和输出是什么？如果移除它，系统会出现什么具体错误？

组件学习至少需要阅读对应的 [组件说明](组件说明/README.md)，不能只根据生成代码或 IDE 自动补全理解 API。

### 2.2 阅读代码

先阅读类注释、字段注释和方法注释，再阅读实现。代码中的注释应解释设计动机、生命周期、线程安全边界和关键参数，而不是重复语句含义。

### 2.3 小实验验证

优先使用最小实验验证一个概念，例如：

- 启动 Netty 服务端并观察端口监听日志。
- 使用两个 TCP 客户端发送拆分的数据片段，验证分帧行为。
- 向 `Scene` 提交命令，验证命令只在 `scene-tick` 线程执行。
- 关闭连接，观察 Channel、Session 和场景实体的清理顺序。

### 2.4 复盘和修改

每个阶段完成后，至少能够独立回答：

- 请求从连接建立到业务逻辑执行经过哪些对象？
- 哪些代码运行在 Netty EventLoop，哪些代码运行在场景 Tick 线程？
- 为什么不能在网络线程直接修改玩家坐标？
- 半包和粘包分别是什么，当前代码由哪个组件处理？
- 如果某个客户端发送非法数据，服务端在哪一层拒绝？

## 3. 当前阶段：Netty 入门

当前代码只完成服务端启动、TCP 连接初始化、长度字段分帧和场景 Tick 骨架，还没有完成完整消息编解码、Session、登录和业务分发。阅读顺序建议如下：

1. `GameServerApplication`：进程如何组装模块和关闭资源。
2. `GameServer`：`ServerBootstrap`、Boss/Worker `EventLoopGroup` 和监听端口。
3. `GameChannelInitializer`：每条客户端连接如何创建自己的 `ChannelPipeline`。
4. `Scene`：网络线程为什么要把命令投递给场景 Tick 线程。
5. 下一阶段的消息头和 Protobuf 编解码：字节如何变成结构化消息。

当前组件文档：

- [Netty 组件说明](组件说明/Netty.md)
- [Protocol Buffers 组件说明](组件说明/Protocol%20Buffers.md)

## 4. 验收标准

“代码编译通过”只证明语法和类型正确，不代表已经掌握。学习验收需要同时满足：

- 能不看注释解释核心类之间的调用关系。
- 能修改一个参数并预测测试或日志变化。
- 能针对异常输入说明拒绝位置和清理路径。
- 能通过测试或实验结果证明自己的判断。
