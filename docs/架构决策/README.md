# 架构决策记录

## 1. 文档目的

架构决策记录（ADR）用于保存“为什么选择这个方案”，而不仅是记录最终代码。后续面试复盘时，需要能够说明背景、选择、替代方案、代价和未来变化条件。

## 2. ADR 模板

```markdown
# ADR-XXX：决策标题

## 状态

提议 / 已采纳 / 已替代

## 背景

描述需要解决的问题和约束。

## 选择

说明采用的方案。

## 原因

说明为什么选择它，以及放弃了哪些替代方案。

## 代价

说明复杂度、性能、运维或学习成本。

## 验证

说明通过什么测试、实验或运行结果验证。

## 未来变化条件

说明什么情况下需要重新评估这个决策。
```

## 3. 初始决策目录

计划记录以下决策：

- `ADR-001-为什么选择TCP.md`
- `ADR-002-为什么选择Protocol Buffers.md`
- `ADR-003-为什么使用单线程Scene.md`
- `ADR-004-为什么实时逻辑不依赖Kafka.md`
- `ADR-005-为什么第一阶段不拆微服务.md`
- `ADR-006-为什么Spring Boot只做外围管理接口.md`
- `ADR-007-为什么采用整数坐标.md`

当前先建立记录规范，具体 ADR 在对应方案完成实验验证后补充，避免把未经验证的推测写成结论。
