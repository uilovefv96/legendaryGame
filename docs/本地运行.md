# 本地运行规划

## 当前状态

当前已建立 Maven 多模块工程和服务端启动骨架。需要 Java 21 和 Maven。执行 `mvn -version` 时，Java version 必须为 21；如果 Maven 仍使用 Java 8，需要检查 `JAVA_HOME` 和 Maven Runner 的 JDK 配置。

## 第一阶段目标命令

当前根目录支持：

```text
mvn clean test
mvn -pl game-server/game-server-bootstrap -am test
mvn -pl game-server/game-server-bootstrap -am install
```

如果在独立 PowerShell 中执行，先确认 `mvn -version` 输出的 `Java version` 为 21。Maven 的 `release` 配置只能约束编译目标，不能把运行 Maven 的 JRE 自动切换为 Java 21。

服务端启动后应输出：

```text
Game server started
Netty listening on port 9000
```

启动服务端推荐分两步执行。第一步先安装服务端依赖模块到本地 Maven 仓库：

```text
mvn -pl game-server/game-server-bootstrap -am install -DskipTests
```

第二步使用 `game-server-bootstrap` 模块自己的 `pom.xml` 启动入口类：

```text
mvn -f game-server/game-server-bootstrap/pom.xml exec:java
```

不要使用 `mvn -pl game-server/game-server-bootstrap -am exec:java` 直接启动；`-am` 会把根项目也加入 reactor，`exec:java` 可能被施加到没有 `mainClass` 的根项目上。

Bot 联调需要先启动服务端，再在另一个 PowerShell 执行。第一步安装 Bot 及依赖模块：

```text
mvn -pl game-bot -am install -DskipTests
```

第二步使用 `game-bot` 模块自己的 `pom.xml` 运行 Bot：

```text
mvn -f game-bot/pom.xml exec:java
```

Bot 默认连接 `127.0.0.1:9000`，账号名为 `bot-001`。可以通过 JVM 系统属性覆盖：

```text
mvn -f game-bot/pom.xml exec:java -Dgame.bot.host=127.0.0.1 -Dgame.bot.port=9000 -Dgame.bot.account=bot-001
```

当前已验证的 Bot 输出应包含：

```text
Bot login success
Bot heartbeat response
Bot finished login and heartbeat check
```

## 本地依赖顺序

第一阶段只要求 Java 21。MySQL、Redis、Kafka 通过 Docker Compose 预留，等持久化和事件阶段开始后再启动。

## 验证要求

每次阶段性改动后至少执行：

```text
mvn clean test
git diff --check
```

若当前环境没有 Git 仓库或命令不可用，应在交付说明中明确记录，不把未执行的命令描述为已通过。
