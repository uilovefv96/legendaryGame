# 个人学习画像

## 1. 文档目的

本项目服务于两件事：补齐 Java 游戏服务端能力，以及把已有企业级 Java 后端经验转化为真实、可验证的求职作品集。

学习计划不从 Java 基础重新开始，而是从已有能力出发，重点补齐实时游戏服务端的运行模型。

## 2. 已有能力

根据当前简历，已有能力主要包括：

- 约 9 年 Java 开发经验。
- Spring、Spring MVC、MyBatis、Spring Boot、Spring Cloud。
- MySQL、Oracle、MongoDB、Redis。
- Elasticsearch、NebulaGraph。
- Kafka、RocketMQ、ZooKeeper。
- Linux、Docker、线上部署和问题排查。
- JVM 内存模型、垃圾回收和常见性能问题分析。
- 大规模数据检索、聚合统计、动态查询构建和数据导出。
- 缓存穿透、缓存击穿、缓存策略和接口性能优化。
- 消息异步解耦、可靠性处理和分布式事务场景。
- ARMS、SLS 等监控和日志分析工具。
- 需求评审、任务拆分、技术方案设计、Code Review 和跨团队协作。

## 3. 相关项目经验

### 3.1 企知道平台

参与企知道“查企业”核心业务线和企业数据平台建设，涉及企业搜索、企业图谱、数据观察台和首页信息流等场景。

已有实践包括：

- 基于 Elasticsearch 支撑企业名称、行业、地区、成立时间等多维度检索。
- 基于 NebulaGraph 存储企业节点和关系边，实现企业关联关系查询和图谱展示。
- 基于 Redis 设计多级缓存，应对高并发查询和缓存异常场景。
- 基于 Kafka 处理异步数据同步和消息解耦。
- 使用 Elasticsearch Aggregation 完成多维统计和下钻查询。
- 使用 Scroll / Search After 完成大数据量异步导出。
- 使用 ARMS、SLS 分析慢查询、系统瓶颈和 GC 问题。

### 3.2 老司机游戏盒子

已有游戏相关业务经验，项目包含动态匹配、战队管理、网吧计费和内容社区等场景。

已有实践包括：

- 使用 Elasticsearch Geo 和 BitMap 实现地域、段位匹配。
- 支撑高峰期匹配请求。
- 使用 RocketMQ 事务消息处理房间创建和支付回调等一致性场景。
- 使用 Redis、布隆过滤器和互斥锁处理缓存异常。
- 使用 Sentinel 做限流、熔断和降级。

这些经历说明已经接触过游戏业务外围和高并发平台，但仍需要通过 Legendary Online 补齐“实时游戏核心服务端”的证据。

## 4. 重点补齐能力

### 4.1 网络和连接模型

- Java NIO 基本运行模型。
- Netty `EventLoop`、`Channel` 和 `ChannelPipeline`。
- TCP 字节流、半包、粘包和自定义分帧。

### 4.4 实时系统工程化

- 多客户端集成测试。
- 故障注入和恢复验证。

## 6. 学习策略

每个新主题采用以下方式：

```text
已有经验对比
    -> 新概念说明
    -> 最小实验
    -> 项目实现
    -> 异常和性能验证
    -> 面试表达和复盘
```

例如学习 `Scene Tick` 时，需要把它与熟悉的 HTTP 请求模型、MQ 消费模型进行对比，明确它为什么不能简单套用 Controller 或 Consumer 的处理方式。

## 7. 阶段性目标

### V0：基础模型和实验

- 理解 Java NIO 和 Netty 基本线程模型。
- 理解 Protocol Buffers 和自定义消息头。
- 理解 CommandQueue 和 Scene Tick。
- 能通过最小测试解释线程边界。

### V1：可运行垂直切片

- 登录和进入场景。
- 两个客户端同时在线。
- 移动意图、服务端权威坐标和位置广播。
- 普通攻击、怪物死亡和奖励。
- 断线清理和重连恢复。

### V2：就业展示版

- Java Bot 联调和压测。
- 故障实验和性能报告。
- MySQL、Redis、Kafka 的合理边界实践。
- Spring Boot GM 管理接口。
- 监控指标、JFR 和 Docker 部署。
- 完整的组件说明、功能说明、ADR 和就业证据矩阵。

## 8. 使用规则

每增加一个模块或组件，都要检查它是否补齐了真实短板。如果只是重复已经熟悉的技术，不为了增加技术名词而引入。项目优先把 Netty、Scene Tick、服务端权威、实时同步、Bot 和故障排查做深。
